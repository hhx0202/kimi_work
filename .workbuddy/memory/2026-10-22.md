## 迁移 Cloudflare Pages（22:40 ~ 23:40，已上线）
- **诊断出真正的根因**：用户说"慢"其实是**图片加载不出来**。实测 github.io 单张 118KB 立绘 30 秒只收到 82KB（**2.7 KB/s**）、app.js 247KB 只收到 48KB，状态码都是 200 —— 是传输被限速，不是文件缺失也不是图片太大。
- **对比测试**：Cloudflare CDN（cdnjs）40 KB/s、jsdelivr **5.9 KB/s**、EdgeOne 旧域名返回 **401**（站点已不可用）。结论：github.io 在国内基本不可用。
- **踩了两个域名坑**：① 先用 Workers 的 Upload assets 建，拿到 `broad-mountain-20f5.515876630.workers.dev`，结果 **workers.dev 被 DNS 污染**（解析到 Facebook `face:b00c`/`128.242.240.244`），国内打不开；② `pages.dev` 解析正常（`172.66.x.x`），所以必须走 Pages。
- **新版 UI 找不到 Pages 入口**：`dash.cloudflare.com/<account>/pages/new` 已 404，左侧菜单没有 Pages，Create application 只给 Workers 流程 —— 这就是用户找不到 "Build output directory" 的原因（该字段只在 Pages 流程里）。
- **最终用命令行落地**：`npx wrangler@latest login --device`（设备码授权，适合无浏览器交互的沙箱）→ `wrangler pages project create kimi-work --production-branch master` → `wrangler pages deploy D:/AI/kimi_dist --project-name kimi-work --branch master`。615 文件上传 29.5 秒。
- **上传目录 `D:/AI/kimi_dist`**（项目外，避免污染仓库）：只放 `index.html intro.html css js assets`。**绕开两个坑**：直接发仓库根目录会因 `.git` 的 31.6MB pack 超过 Cloudflare 单文件 25MiB 上限而构建失败；就算不超限也会把 `.git`/`sql`/`.workbuddy/memory` 全公开。
- **实测结果（成功）**：立绘 118KB → 4.7 秒（24.9 KB/s）、app.js 252KB → 2.1 秒（118 KB/s），全部 200 完整下载。用户确认"任务列表都在，图也能出来"。
- **DNS 副产物**：用户家路由器（192.168.2.1 小米）只返回 AAAA 不返回 A，`kimi-work.pages.dev` 本地解析成 Non-existent domain；`ipconfig /flushdns` 无效，公共 DNS（223.5.5.5 / 119.29.29.29）正常。
