- **排查耗时最久的原因：account id 被我 OCR 读错**。从用户截图 URL 里读成 `306aae3e2cbdfa6f127c4604cdf7911c1`，正确的是 `306aae3e2cbdaf6a127c4604cf7911c1`（`fa6f`→`af6a`、`cd`→`cf`）。这个错 id 让 `GET /accounts/<id>/pages/projects` 一直返回 `Authentication error [code: 10000]`，导致连续 5 次误判成 "token 权限不足"。

- **workflow 必须显式传 `CLOUDFLARE_ACCOUNT_ID`**：中途为了排查改成"让 wrangler 自动检测"，结果触发 `Failed to automatically retrieve account IDs`（同上，token 没有列账号权限），又白跑一轮。
- **wrangler-action@v3 弃用**：它内部 npx 失败只报 `The process '/usr/local/bin/npx' failed with exit code 1`，完全看不到 wrangler 的真实错误（还有 Node 20 deprecated 警告）。改成 `run: npx --yes wrangler@4 pages deploy ...` 后错误立刻可见。
- **诊断步骤的价值**：workflow 里加一步打印 token 长度、verify 结果、accounts 列表，是这次定位的关键；但要注意 GitHub 会把所有匹配 secret 的值 mask 成 `***`。

## 场景卡 ex 问题诊断 + 两套方案实验（01:05 ~ 01:25）
- **为什么会混着 ex**：`tools/fetch_scenes.py` 按 `151C{图鉴号:03d}.png` 抓「收集啦151」，而该系列 **12 只只有 ex 版、没有普卡**（官方设计，ex 占据了图鉴位）。名单：3 妙蛙花、6 喷火龙、9 水箭龟、24 阿柏怪、38 九尾、40 胖可丁、65 胡地、76 隆隆岩、115 袋兽、124 迷唇姐、145 闪电鸟、151 梦幻。其余 139 张是普卡。
- **官方简中资源无法补齐普卡**：四个子包（旅/惊/望/聚）是同一套 151 张卡表；简中其他系列（剑&盾 SET A/B、宝石包）只命中九尾 1 只。要全普卡只能自制或换日文卡（后者破坏中文一致性）。
- **卡面几何（400×559 的 jpg）**：插画外框 `(17,56,383,268)`，去掉内框后的内容区 `(19,58,381,266)`；名字条 y14-48；HP 数字 x297-346；图鉴行 y268-284；招式1 y330-356、招式2 y403-429；伤害数字右对齐到 x=368；底部编号 y531-546 / x84-130。
- **合成卡面可行**：借同属性普卡卡框（如妙蛙草 2.jpg），贴 ex 插画 + 用 `erase()` 逐行左右插值抹掉原文字再重绘。中文用 `msyhbd.ttc`（粗）/`msyh.ttc`，名字 30px、招式 22px、伤害 24px、图鉴行 12px。样张效果接近真卡。
- **异色处理**：只旋转 HSV 里「H 28-75 且 S>0.35」的像素（=黄色系），背景森林不受影响，皮卡丘变蓝；要比"滤镜感"更高级必须走 AI 图生图。图生图样张（银白闪粉皮卡丘）质量好、构图一致，但**生成图右下角带「AI生成 WORKBUDDY」水印**，裁切到插画比例时正好切掉（1536×1024 裁 y80-944 → 无字）。
- **环境坑**：`pip` 指向 Python 3.8，而 `python` 是 3.13 → 装库必须用 `python -m pip install`；已装 pillow 13 / numpy 2.5。
- 预览页与样张在 `_preview/`（临时，定案后删）。

## 伊布分支进化死锁修复 + 重复培养三折（01:26 ~ 01:36）
- **死锁成因**：`evolvePm` 直接把 pm 的 `pokedex_no` 改写成进化后形态 → 基础形态从 `S.pokemons` 消失；`dexGot()` 又把祖先链全点亮 → `ownedNumbers()` 含 133 → `catchOne` 的「必出新」永久剔除伊布 → 兄弟分支永远拿不到。
- **修复**：`branchPending(no)`（ev 分支还有未获得目标）→ `catchOne` 允许该基础形态回池；`evolvePm` 只列未集齐的分支；集齐后自动消失。
- **三折规则（用户定）**：分支基础形态只要已经养出过至少一只，再次培养需要 `EVO_EXP_1 × 0.3 = 90`。配置项 `CONFIG.BRANCH_REPEAT_RATE`。
- **统一阈值**：新增 `evoNeedExp(no)`，`expThreshold` 和 `canEvolve` 都调它——之前两处各写一份 `needExp`，改一处必漏另一处（会导致「进度条显示满了却进化不了」）。
- **实测**：CDP 注入「已有水伊布 + 新伊布」→ `EXP 0/90`、进化链正常、图鉴里伊布仍亮（不是剪影）、`canEvolve` 返回「经验 0/90」一致。测试 356 全绿。
- **图鉴语义**：`dexGot` 点亮祖先链 = 「曾经收集过」，不代表手里有；点开未持有的已收集形态会走 `showDexDetail` 的图鉴卡（不是剪影）。
