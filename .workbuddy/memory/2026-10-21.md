## 手机端排序修不动 / 闪耀卡改成可用道具 / 连清不再送球
- **手机上「长按标签弹出放大镜、拖不动」的根因**：排序模式里 `touchstart` 是 `{passive:true}`，`preventDefault()` 根本没法调，系统长按选字（iOS 的放大镜、安卓的选区手柄）接管手势后 `touchmove` 全被吞掉 → 表现为「出现了个放大镜，动不了」。修法：排序模式单独加一个 **非 passive** 的 `touchstart`（`if(!quickSorting) return;` 让原来的 passive 处理器让路），里面 `e.preventDefault() + clearSel()`，CSS 再补 `#pt-quick-list.sorting .quick-chip{touch-action:none;-webkit-user-drag:none}`。普通模式的单击添加/长按编辑仍走原 passive 处理器，已验证不受影响。
- 验证必须用**真实触摸序列**（`Input.dispatchTouchEvent` touchStart → 停 300ms → touchMove → touchEnd），不能用 elementFromPoint 造假，否则测不出系统手势抢占。另外触摸坐标是**视口坐标**，目标在折叠线以下要先 `scrollIntoView`，不然点了个空气。
- 连清奖励改成**只给闪耀卡**（用户明确不要球）：`STREAK_REWARD_BALLS` 删除，换 `STREAK_REWARD_SHINY`（默认 1），`shinyReward()` 读取；`claimStreak` 只写 `DB.addItemLog('shiny', n, '必做全清N天_日期')`，不再 `S.balls +=`，也不再随机自动点亮一只。
- 闪耀卡做成**可用道具**（原来奖励一领就随机变闪，用户不知道「卡」怎么用）：`S.shinyCards = await DB.getItemCount('shiny')`（refreshAll 里加一路），宝可梦页最上方 `.shiny-bar` 金条（有库存才出现）→ 点「使用」进入 `shinyPickOn` 选择态 → 卡片虚线金边 + 「用它 ✨」，已闪的置灰 `locked` → 点一张 `applyShinyCard(pmId)`：扣一张卡（`addItemLog('shiny',-1,...)`）+ `addShinyCopy` 多一张 ✨ 卡 + `showShiny` 动画。离开宝可梦页自动退出选择态（`render()` 里 `if (S.tab!=='pokemon') shinyPickOn=false`）。
- 规则：**任何阶段（基础/一阶/二阶）都能用**，一张卡只管一只、只管它自己的编号；基础形态闪了以后进化出来的新卡仍是普通卡（图鉴层面家族算已收集）。要家族自动继承闪耀的话得另做。

## 每日叮嘱改成「自动沿用最近一次」
- 需求：家长不用每天重打，昨天的叮嘱自动带到今天，在此基础上改。
- 实现只在数据层：`DB.getNote(date)` 当天键**不存在**时，向前取「最近一条更早日期」的值（demo 遍历 `P+'note_'` 前缀键取最大日期；supabase 走 `.lt('log_date',date).order('log_date',{asc:false}).limit(1)`）。UI 不用改，`refreshViewNote` / `refreshParentNote` 自动生效。
- **必须区分「键不存在」和「键是空串」**：`lsGet(key, null)` 用 `null` 当"没有这个键"的哨兵，空串=家长明确清空（从这天起不显示），后面的日期也因为最近一条是空而返回 null，不会翻回更早的。若用 `lsGet(key,'') || null` 就分不出来，清零会被前一天覆盖回来。
- 家长按钮预览要把换行压成空格：`String(S.parentNote).replace(/\s+/g,' ').trim()`，否则 slice 出来的文本带 `\n` 把按钮撑成两行。
- 编辑器提示改为「今天还没单独写过的话，这里会先带出最近一次的叮嘱，改完保存就只算今天的。留空保存 = 从今天起清除。」
- 实测：昨天写→今天/明天都沿用；今天自写→用今天的；今天清空→今天和明天都空；家长切到「明天」也能看到内容（可提前布置）；孩子端当天卡片正常。

## 原生 prompt/confirm 全部换成自绘弹窗（预览面板兼容）
- **根因**：WorkBuddy 里 present_files 打开的预览面板是 iframe/webview，宿主没给 `allow-modals`，原生 `prompt()/confirm()/alert()` 全部被禁用，点「家长」就报 `Uncaught Error: prompt() is not supported`；手机/电脑普通浏览器不受影响，所以用户两边表现不一致。
- 修法：新增 `askConfirm(msg, {title, okText, danger})`（Promise<boolean>，Esc=取消/Enter=确定/点遮罩=取消）和 `openParentAuth()`（密码输入弹窗：错密码红字「密码不对，再试一次」+ `.modal.shake` 抖动重放，`void box.offsetWidth` 强制重排才能重放同一动画类；Enter 提交、Esc 取消，`inputmode="numeric"` 唤数字键盘）。全项目 6 处 `confirm()` 一并替换（delTask/err-clear/enterDemoMode/exitDemoMode/resetDemo/undoPoint），调用点补了 await。
- 验证方法：仓库里临时放一个 `__sandbox_test.html`（iframe `sandbox="allow-scripts allow-same-origin allow-forms"`，故意不带 allow-modals）复现被禁用环境，CDP `Log.entryAdded`/`Runtime.exceptionThrown` 监听确认无报错；测完即删。
- 手机端有一个 `[DOM] Password field is not contained in a form` 的 verbose 提示，无功能影响。
