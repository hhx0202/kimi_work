# 🏝️ 佑佑的任务岛

给孩子的作业 + 打卡激励工作台。家长布置任务，孩子打卡赚积分，用积分捕捉/升级/进化宝可梦。纯前端 + Supabase 数据库，免费部署。

## 快速运行

无需任何构建工具，纯静态页面：

- **Windows**：双击 `start.bat`（自动打开浏览器，并打印手机访问地址）
- **Mac/Linux**：`bash start.sh`
- 或手动：`python serve.py` / `python -m http.server 8000` → 浏览器打开 http://localhost:8000

**手机打开（本地演示）**：手机和电脑连**同一个 WiFi**，在手机浏览器输入电脑打印的那个地址（如 `http://192.168.x.x:8000`）。电脑防火墙若弹窗，点「允许」。

**给孩子 / 别的家长演示**：打开 `intro.html`（介绍页）→ 点「立即试玩」。家长中心顶部有「🎮 进入演示模式」入口：

- **进入演示模式**：切换到一套**独立的演示数据**（`kmd_` 前缀，和真实数据完全隔离，不联网），孩子随便玩，怎么玩都不影响真实数据；部署到网上后同样可用
- **退出演示模式**：家长中心 →「↩ 退出演示」，回到真实数据
- **重置演示数据**：演示中家长中心 →「🔄 重置演示数据」，重新生成示例任务
- **演示数据自带测试内容**：18 只宝可梦（覆盖基础 / 一阶 / 最终形态 / 无进化链 / 闪耀形态 / 差 20 分就进化 / 分支进化的伊布 / 传说超梦）、1200 积分、45 个精灵球，打开就能直接测喂养、进化、闪耀形态、图鉴。老演示数据升级时会自动补一批（只补一次，不重复）

## 任务系统

**四种类型（任务属性） + 必做/选做**：

| 类型 | 属性 | 说明 |
|---|---|---|
| daily | 重复 | 每天都要做（每日打卡），在「新建任务 → 重复」单独建 |
| once | 单次 | 当天做一次、做完消失（「批量添加单次任务」加这类） |
| weekly | 多日 | 带截止日期的长期任务，拆成子任务独立计分 |
| child | 子任务 | 多日任务的子项，各自带分数，完成得自己的分 |

- **必做/选做**：任务分「必做 / 选做」，孩子端分两区平铺展示，卡片显式标注属性
- **多日任务**：子任务各带分数，进度按已得/总分算；全部完成额外加分（可配）、超期每天扣分（可配）
- **类别记忆**：家长填的新类别自动记住（下拉可选）；「🏷️ 管理历史类别」可删。类别顺序 = `DEFAULT_CATEGORIES`，只在家长还没手动排序时作为默认顺序
- **孩子端规则小抄**：说明怎么拿分（必做全清 +5、选做全清 +5、连续 7 天必做全清送闪耀卡、待确认等）

**奖励分层**：
- 完成单个任务 → +任务积分
- 每日**必做**全部完成 → +`REQUIRED_DONE_BONUS`（默认 5）
- 每日**选做**全部完成 → 再 +`OPTIONAL_DONE_BONUS`（默认 5）
- 连续 7 天必做全清 → 任务页最下方进度条点「领取」得 ✨ 闪耀卡（宝可梦页点「使用」选一只宝可梦用掉）
- 多日任务完成 → 额外奖励（可配）

### 待确认积分（防乱点）

孩子点「完成」立即变 ✅、发彩带、出战宝可梦照常加经验、连击照算，但**积分先进"待发放池"，余额不变**。家长进入家长中心，看到「📦 待确认积分」卡片：

- 逐条可取消勾选 → 一键「确认发放选中的积分」
- 每条可点 ✖ **放弃**（不发分并恢复该任务未完成）
- 确认后发现错了，在**积分流水**里点「↩」撤销 → 扣回积分 + 恢复未完成

余额 = 已确认发放的积分之和，孩子没法自己乱点花掉未确认的分。

### 家长消息（孩子端任务页顶端）

家长做了需要孩子知道的事，会在他**任务页最顶端**留一张消息卡，点「知道啦」才消失（多条时可一键全部确认；底部「任务」页签同时显示未读角标）：

- 🔴 **送精灵球**：家长奖励球 → 「家长送了你 1 个精灵球，现在一共有 N 个」
- ➖ **扣分**：家长扣分 / 多日任务超期自动扣分 → 带原因
- 🏅 **审批通过**：家长在「待确认积分」里确认 → 哪项任务、加了多少分（一次确认多项会合并成一条并列出任务名）
- 🎁 **额外奖励积分**：家长在家长中心直接发分 → 带上原因

消息存在本机（真实/演示数据各自独立），确认后才清除，不会因为刷新页面丢失。

### 出错提示与错误日志（方便排查）

页面出现异常时会**顶部弹一条红色提示**，写明「脚本错误 / 异步错误 / 数据库错误」和具体信息，可展开看堆栈、一键复制，发给开发者就能定位：

- 全局捕获：`window.onerror`、`unhandledrejection`，以及数据库层 `console.error('[DB …]')`（带 Supabase 的 `code / details / hint`）
- 同类错误 5 秒内只累计次数（×N），不会刷屏；最多留档 30 条，存在本机
- 家长中心底部「🐞 错误日志」可查看全部记录、展开堆栈、复制全部或清空

**子任务格式（布置多日任务时）**：每行 `名称, 分数`（分数可省默认 10 分；末尾写「选做」=非必做）
```
第1篇课文,10
第2篇课文,10
习作,15,选做
```
总分自动 = 子任务分之和，进度按已得/总分算。

**多日任务编辑**：家长端点多日任务行 ✏️ 编辑，可改标题/提示/截止/子任务/完成奖励。

**批量添加**：页面上的「📥 批量添加」框**常驻可见**，直接粘贴就行，**每行一个任务**。类别 / 分数 / 选做用中括号 `[类别] [分数] [选做]` 或小括号 `(类别) (分数) (选做)`（中英文括号都行）指定，不写用默认：类别「作业」、分数 10、必做；任务名整行即名称，末尾可加 `{小提示}`。粘贴老师发来的作业清单（一行一条）能直接建任务，不会拆坏标题里的逗号；行尾「空格+数字」会当成分数（上限 100），如 `练字一页 10`。

**布置到别的日子**：同一个框里**第一行写日期**就行，不用换地方——支持 `10-20` / `10月20日` / `今天` / `明天` / `周一`；后面几行是那天要做的任务，直到下一个日期行。任务只出现在对应那天、错过当天不再出现。不写日期就全部加到当前查看的那天。

> 批量加的都是「单次任务」（当天做一次、做完消失）；想加「重复」的每日任务请用「新建任务 → 重复（每天都有）」单独建，避免批量复制误建出一堆重复任务。写法细节见「批量添加」下方的「格式说明」（默认收起）。

**任务关联**：已建好的任务可在编辑弹窗「所属多日任务」里选一个多日任务，成为它的子任务（独立计分、进度归入），也可取消关联恢复独立任务。

**远程接口（AI agent 改任务）**：项目自带 Supabase REST API，本地 agent 可按 [`AGENT-API.md`](AGENT-API.md) 的规范直接增删改任务——家长发一句话，agent 解析成任务后调用接口，无需写后端。

### 常用任务（家长端）

家长端有一排**常用任务标签**（图标 + 名称 + 分数 + ✕），日常布置全靠它：

- **单击标签**：弹出添加任务表单（名称/类别/分数/必做选做/布置到哪天都已预填），点「确认添加」立刻加到任务列表
- **长按标签**：打开编辑标签页，只改名称和分数（不影响已布置的任务）
- **排序**：点标题右侧「排序」，按钮变「确认」；长按标签拖动即可换位，松手已保存，点「确认」或点页面别处退出
- **＋**：新增一个常用任务标签（图标随机分配），**✕**：从常用任务里删掉
- 首次使用会按 `js/app.js` 顶部 `TPL` 数组预置一批（语文作业/数学作业/跳绳…），存 localStorage（`km_quick_tasks`）

## 宝可梦系统

- **捕捉必新**：消耗 1 球 → 一定是**没抓过的**新宝可梦（绝不重复），稀有 15%；**只出基础形态**——进化后的形态不能抓，只能靠喂养进化获得（伊布这类分支进化会在进化时让你选一只）；基础形态全部抓齐后不再扣球
- **出战伙伴**：⭐ **出战**的宝可梦是你的伙伴，每次完成任务它 +1 exp；也可用积分喂糖果（1 分 = 1 exp）。喂糖果支持**自定义积分**，余额够时还有「🚀 刚好进化」一键补齐到下一阶段；喂完**停在它的详情页**（不会退回列表）
- **进化（无等级）**：经验满一管即进化，不花积分、不升等级。三段进化：基础满 **300** → 一阶，一阶满 **500** → 二阶，二阶再攒满 **100** → ✨ 闪耀形态；进化动画 → 图鉴点亮
- **闪耀形态✨**：不由捕捉产出，且统一「额外多一张卡」——普通卡留着，另生成一张 ✨ 卡。来源两处：① 最终形态攒满 100 经验（自动）；② 连续 7 天必做全清领到的**闪耀卡**，在宝可梦页点「使用」后自己挑一只用掉（任何阶段都能用，一张卡对应一只）。**闪耀形态按整条进化链生效**：家族里任意一只闪耀形态，图鉴中该家族所有阶段都会点亮并标 ✨（"捕捉必新"也会把整个家族视为已收集）。**闪耀会沿进化链往后继承**：闪耀卡用在基础形态上之后，这只（普通卡）进化出来的形态也直接是 ✨，不用再喂一只；反过来不会往前传染（✨ 只在后面的形态时，前面的基础卡进化还是普通卡），目标编号已经有一张 ✨ 卡时不会再生成第二张
- **小卡排序**：`我的宝可梦` 右侧「↕ 排序」——捕获顺序 / 捕获倒序 / 编号顺序 / 属性 / **进化阶段升序（基础→一阶→二阶）/ 阶段降序**（进化阶段 = 卡牌里的「基础 / 1阶进化 / 2阶进化」）
- **顶部捕捉区**：一行「精灵球 ×N」+ 两个并排按钮「捕捉」「买球 100 分」，规则收进折叠的「宝可梦小抄」；**捕捉和买球都会先弹确认**（写清花掉几个球 / 多少积分），防手滑
- **卡牌**：宝可梦页是小卡牌网格，点卡翻牌打开 PTCG 风格大卡（属性边框色 + 场景背景 + **4 个招式** + 进化链 + **图鉴介绍**）
- **招式**：每只 4 个招式来自 PokeAPI 官方习得表（`js/pokemon-moves.js`，`tools/fetch_moves.js` 生成）：优先等级习得、保证本系代表招式（火系必带喷射火焰这类）、同属性最多两招，最后一招常是变化招式。卡面上按行显示「属性标签 · 招式名 · 威力 · 物理/特殊/变化」，**点一行展开官方中文说明**；没有招式数据时回落到该属性的默认招式
- **卡面属性特效**：详情卡按属性自动配一种持续的动态氛围——火=火星上飘、水=整卡水波（浪花纹无缝平铺 + 水下蓝调 + 底部水滴波纹一圈圈荡开 + 上升气泡 + 水光扫过）、电=电光闪烁+电流扫过、草/虫=叶片飘落、冰=雪花缓落、毒=紫绿毒雾柔和弥漫 + 上升毒孢 + 底部毒气呼吸、超能/妖精/龙/幽灵=灵光呼吸+星点、岩石/地面/钢/格斗=尘土飘散、飞行/一般=气流掠过。闪耀形态额外叠一层金色星雨 + 全息光带
- **图鉴**：151 只都有 PokeAPI 官方中文介绍，未收集显示剪影（**点格子也能打开剪影卡**，不剧透名字/属性/招式，只提示去捕捉），闪耀家族整链带 ✨。**进化不会抹掉前一阶**：当前形态的所有前置形态都保持点亮；点图鉴格子或详情卡里进化链上的名字，都能打开**那个形态**的详情（不是自己当前那只时是只读卡，可一键跳到"我的 XX"）

## 数据库表（Supabase）

| 表 | 用途 | 关键字段 |
|---|---|---|
| `tasks` | 任务 | title, category, points, schedule(daily/once/weekly/child), deadline, parent_id, percent, required, active, start_date/end_date(单次绑定日期), hint(小提示), sort(顺序), bonus(多日完成奖励) |
| `task_logs` | 打卡 | task_id, log_date, completed, progress, note（task_id+log_date 唯一；删除任务保留历史） |
| `pokemon` | 宝可梦 | name, pokedex_no, level, exp, shiny |
| `point_logs` | 积分流水 | log_date, amount(±), reason, confirmed(已发放), task_id, created_at(发生时间)（余额 = SUM(confirmed)） |
| `item_logs` | 物品流水 | item('ball'), amount(±), reason（球数 = SUM） |
| `notes` | 每日叮嘱 | log_date(唯一), note（家长每天写给孩子的话；某天没记录时自动沿用此前最近一条，记空串=从这天起清除） |
| `settings` | 规则设置 | key, value（家长「⚙️ 规则设置」覆盖 config 数值） |

**建表/升级**：全部在 `sql/upgrade_all.sql` 一个文件里（幂等可重复执行），Supabase 只跑它即可。

## 部署上线（Cloudflare Pages + Supabase）

**线上地址：https://kimi-work.pages.dev**

1. Supabase SQL Editor 执行 `sql/upgrade_all.sql`（建表 + 全部升级，幂等可重复）——**本项目线上库已于 2026-10-20 执行完毕**，新环境才需要再跑
2. `config.js` 填 `SUPABASE_URL` + publishable/anon key（`DB_MODE` 已自动判断：localhost/本地打开用演示数据，线上域名用真库）
3. **`git push` 即自动部署**：GitHub Actions（`.github/workflows/deploy-pages.yml`）在推送后把 `index.html intro.html css js assets` 复制进 `dist`，再 `wrangler pages deploy` 到 Cloudflare Pages 的 `kimi-work` 项目
4. 手机/平板收藏 `https://kimi-work.pages.dev/`
